UMA ANALOGIA

Imagine uma central de correspondências por assunto.

Protocolo é um conjunto de regras de comunicação. MQTT usa publicação e assinatura. Apresente os três personagens sem detalhar todos de uma vez. A analogia é uma central de boletins por assunto: uma publicação pode ser distribuída a várias pessoas inscritas. Diferentemente de uma carta comum, a mensagem não leva o endereço de um único destinatário. Os bonecos são uma analogia; no sistema real, publicadores e assinantes são clientes de software. Fonte: MQTT.org — protocolo de mensagens.

O broker é o servidor intermediário, não o protocolo MQTT. Cada cliente mantém sua própria conexão com ele. O broker recebe publicações, verifica quais assinaturas correspondem ao tópico e encaminha as mensagens aos clientes interessados. Não é necessário programar o celular A para abrir uma conexão direta com cada celular B, C ou D. A questão das redes será ilustrada adiante. Avance para revelar uma responsabilidade por vez. Fonte: Eclipse Mosquitto — publicação e assinatura.

As setas representam a iniciativa de conexão: A inicia sua conexão ao broker e B inicia a sua. Depois cada conexão permite tráfego nos dois sentidos, incluindo mensagens que chegam ao assinante. O broker não precisa abrir uma conexão nova de fora para o celular. Isso simplifica a comunicação entre clientes atrás de NAT e em redes diferentes, mas não elimina a necessidade de conectividade, roteamento, DNS e portas permitidas até o broker. Se o broker estiver numa rede privada sem acesso pelos clientes, a comunicação não funcionará. No exemplo da aula é usado wss://mqtt.acilab.com.br: MQTT sobre WebSocket seguro, por uma porta que a rede precisa permitir. Não é necessário pedir o IP de outro celular nem hospedar um servidor em cada aparelho. Fonte: HiveMQ — conexões MQTT e NAT.

MQTT é um protocolo de mensagens. O broker é o servidor que recebe as publicações e as distribui aos clientes que possuem assinaturas correspondentes. Publisher e subscriber são papéis: o mesmo celular pode publicar e assinar. A conexão de cada cliente fica aberta para receber novas mensagens.

Função publish

mqttService.js
import mqtt from 'mqtt/dist/mqtt.esm';
import { BROKER, TOPICO } from './config';

const client = mqtt.connect(BROKER);
client.on('error', console.error);
client.on('connect', () => {
  client.subscribe(TOPICO);
});

export function publish(mensagem) {
  client.publish(TOPICO, mensagem);
}

Atividade

  • Acrescente publish(mensagem).
  • Publique usando o cliente já criado.
  • Mantenha a conexão aberta para os próximos envios.
publish usa a instância compartilhada; não conecta nem encerra a cada envio. MQTT.js permite publicar antes da conexão e mantém mensagens QoS 0 em fila por padrão. Isso não confirma entrega ou leitura. Fonte: https://github.com/mqttjs/MQTT.js#client

Função subscribe

mqttService.js · acrescentar ao final
export function subscribe(receber) {
  function onMessage(topico, payload) {
    if (topico === TOPICO) {
      receber(payload.toString());
    }
  }
  client.on('message', onMessage);
  return () => {
    client.removeListener('message', onMessage);
  };
}

Atividade

  • Acrescente subscribe(receber).
  • Entregue o texto ao callback receber.
  • Na limpeza, remova apenas o callback da tela.
Acrescente subscribe ao mesmo arquivo. O broker já é assinado no evento connect da instância compartilhada; esta função registra quem vai receber o texto na tela. A limpeza remove apenas esse listener. Não use client.end ou removeAllListeners aqui: outras telas podem usar o mesmo cliente.

App.js · assinar e receber

App.js
import { useEffect, useState } from 'react';
import { Button, Text, View }
  from 'react-native';
import { publish, subscribe } from './mqttService';
import estilos from './estilos';

export default function App() {
  const [mensagem, setMensagem] = useState('');

  useEffect(() => {
    return subscribe(setMensagem);
  }, []);
  return (
    <View style={estilos.tela}>
      <Text>MQTT básico</Text>
      <Text>{mensagem || 'Aguardando…'}</Text>
      <Button title="Enviar Olá" onPress={() => {
        publish('Olá, MQTT!');
      }} />
    </View>
  );
}

Atividade

  • Importe subscribe junto de publish.
  • Use subscribe(setMensagem) no efeito.
  • Retorne a limpeza e teste nos dois aparelhos.
O retorno de subscribe é uma função síncrona de limpeza, portanto pode ser retornada pelo useEffect. O App.js conhece apenas texto e estado, sem configuração MQTT. Publique depois de a assinatura estar pronta; QoS 0 e retain false não entregam histórico.

App.js · lista de mensagens

App.js
import { useEffect, useState } from 'react';
import { Button, FlatList, Text, View }
  from 'react-native';
import { publish, subscribe } from './mqttService';
import estilos from './estilos';

export default function App() {
  const [mensagens, setMensagens] = useState([]);

  useEffect(() => {
    return subscribe(texto => {
      setMensagens(lista => [...lista, texto]);
    });
  }, []);
  return (
    <View style={estilos.tela}>
      <Text>MQTT básico</Text>
      <FlatList
        data={mensagens}
        keyExtractor={(_, i) => String(i)}
        renderItem={({ item }) => (
          <Text>{item}</Text>
        )}
      />
      <Button title="Enviar Olá" onPress={() => {
        publish('Olá, MQTT!');
      }} />
    </View>
  );
}

Atividade

  • Guarde as mensagens em um array.
  • Acrescente cada texto com a atualização funcional.
  • Exiba com FlatList e envie três mensagens.
A lista só recebe a publicação quando o evento message chega, inclusive para o próprio emissor. Os dados ficam na memória. A função publish permanece igual ao primeiro exemplo.
