AULA 19 / Entender a persistência

useState lembra até quando?

Estado em memória

useState atualiza a interface. Seu valor não é recuperado automaticamente quando o processo do app reinicia.

Armazenamento persistente

Mantém um valor local para a próxima execução. O app precisa ler esse valor e colocá-lo no estado.

1. Digitar

→
2. Salvar

3. Reabrir

Persistir um dado e atualizar a tela são duas ações diferentes.

Fechar uma tela, colocar o app em segundo plano e encerrar o processo são eventos distintos. Para verificar persistência, encerre e abra novamente o mesmo projeto, sem desinstalar. Fast Refresh pode preservar o estado e confundir a observação.

Um pequeno mapa de chave e valor

A mesma chave

Salvar novamente substitui o valor anterior. Um prefixo ajuda a organizar as chaves do projeto.

Uma chave ausente

A leitura retorna null. Isso é diferente de uma falha na operação.

O prefixo @aula19 é uma convenção de organização, sem efeito de proteção. Os valores são strings. Não importe AsyncStorage de react-native: usamos o pacote da comunidade. Fonte: Uso do AsyncStorage.

AULA 19 / AsyncStorage

Por que usar await?

A confirmação vem depois da gravação
async function salvarApelido() {
  try {
    await AsyncStorage.setItem(CHAVE, 'Nator');
    setMensagem('Salvo!');
  } catch {
    setMensagem('Falha ao salvar.');
  }
}

Uma Promise

A operação termina depois. await aguarda o resultado; catch trata uma rejeição.

await não bloqueia toda a interface. Desabilite o botão enquanto a operação estiver em andamento.

Esse trecho será executado dentro de um componente e depende do import, de CHAVE e de setMensagem apresentados depois. Não use o retorno sem await, porque você teria uma Promise. Sem catch, uma falha pode virar uma rejeição não tratada. A operação nativa é assíncrona; serializar um objeto enorme ainda ocupa o JavaScript.

AULA 19 / AsyncStorage

Três operações para começar

Execute dentro de uma função async com try/catch
import AsyncStorage from '@react-native-async-storage/async-storage';

const CHAVE = '@aula19/apelido';

// Criar ou substituir
await AsyncStorage.setItem(CHAVE, 'Nator');

// Ler: string ou null
const salvo = await AsyncStorage.getItem(CHAVE);

// Remover apenas esta chave
await AsyncStorage.removeItem(CHAVE);

Prefira remover as chaves da funcionalidade. clear() limpa todo o AsyncStorage disponível ao app.

O bloco reúne a API para consulta, não é um programa completo. Na prática, salvar, ler e remover são ações separadas, cada uma com tratamento de erros. clear não limpa o SecureStore. Fonte: API do AsyncStorage.

AULA 19 / AsyncStorage

1. Preparar o estado da tela

App.js · imports e estado
import { useEffect, useState } from 'react';
import { Button, Text, TextInput, View } from 'react-native';
import AsyncStorage from '@react-native-async-storage/async-storage';

const CHAVE = '@aula19/apelido';

export default function App() {
  const [apelido, setApelido] = useState('');
  const [carregando, setCarregando] = useState(true);
  const [ocupado, setOcupado] = useState(false);
  const [mensagem, setMensagem] = useState('');

Cada estado tem um papel

apelido: texto do campo. carregando: leitura inicial. ocupado: gravação ou remoção. mensagem: retorno para a pessoa.

O código continua nos próximos slides. Os trechos pertencem ao mesmo App.js. A CHAVE deve permanecer igual em todas as operações. A mensagem não deve incluir informações sensíveis. Apelido é apenas um exemplo de preferência comum.

AULA 19 / AsyncStorage

2. Ler ao abrir o app

App.js · leitura inicial
useEffect(() => {
    let ativo = true;
    async function carregar() {
      try {
        const salvo = await AsyncStorage.getItem(CHAVE);
        if (ativo) setApelido(salvo ?? '');
      } catch {
        if (ativo) setMensagem('Não foi possível ler o apelido.');
      } finally {
        if (ativo) setCarregando(false);
      }
    }
    carregar();
    return () => { ativo = false; };
  }, []);

Restaurar a interface

A leitura ocorre na montagem. null vira campo vazio com ??. finally encerra o carregamento.

ativo evita atualizar o estado se o componente tiver sido desmontado enquanto a Promise estava pendente. Não é cancelamento da operação de armazenamento. O array vazio indica a leitura na montagem. A tela de carregamento impede edição antes dessa leitura. Em desenvolvimento, Strict Mode pode repetir a montagem.

AULA 19 / AsyncStorage

3. Salvar pelo botão

App.js · ação salvar
async function salvar() {
    if (ocupado || carregando || !apelido.trim()) return;
    setOcupado(true);
    try {
      await AsyncStorage.setItem(CHAVE, apelido.trim());
      setApelido(apelido.trim());
      setMensagem('Apelido salvo. Feche e abra o app!');
    } catch {
      setMensagem('Não foi possível salvar. Tente novamente.');
    } finally {
      setOcupado(false);
    }
  }

Persistir antes de confirmar

O campo não pode estar vazio. O botão fica indisponível durante a escrita. Se falhar, o texto digitado continua no campo.

O componente usa salvamento explícito. Não há um useEffect que grava a cada mudança do apelido: isso evita escrever o estado inicial vazio antes de recuperar o valor salvo. Explique trim para remover espaços nas extremidades. O finally libera o botão tanto no sucesso quanto no erro.

AULA 19 / AsyncStorage

4. Remover do dispositivo e da tela

App.js · ação remover
async function remover() {
    if (ocupado || carregando) return;
    setOcupado(true);
    try {
      await AsyncStorage.removeItem(CHAVE);
      setApelido('');
      setMensagem('Apelido removido do armazenamento.');
    } catch {
      setMensagem('Não foi possível remover. Tente novamente.');
    } finally {
      setOcupado(false);
    }
  }

Duas mudanças

removeItem exclui o valor persistido. setApelido limpa o estado exibido. A tela só é limpa após a exclusão terminar.

Limpar apenas o TextInput deixa o dado persistido e ele reaparece no próximo início. Remover só a chave não muda automaticamente o estado React. Se a exclusão falhar, preservamos o campo e informamos a falha.

Perfil completo: salvar o objeto

App.js · trecho em foco
const CHAVE_PERFIL = '@aula19/perfil';
const PADRAO = { apelido: '', tema: 'claro' };

async function salvarPerfil(perfil) {
  const texto = JSON.stringify(perfil);
  await AsyncStorage.setItem(CHAVE_PERFIL, texto);
}

Um único objeto guarda apelido + tema. O botão Salvar chama salvarPerfil(perfil).

Este é um exemplo independente, com um único App.js para download. salvarPerfil é chamada pelo handler salvar dentro do componente, com await e try/catch. AULA 19 / Guardar um objeto

Perfil completo: ler com um padrão

App.js · trecho em foco
async function lerPerfil() {
  const texto = await AsyncStorage.getItem(CHAVE_PERFIL);
  if (texto === null) return { ...PADRAO };
  const perfil = JSON.parse(texto);
  if (!validarPerfil(perfil)) {
    throw new Error('Formato de perfil inválido.');
  }
  return perfil;
}

Sem chave: usar PADRAO. Com chave: converter, validar e devolver o perfil.

lerPerfil é chamada na montagem por um useEffect com o mesmo padrão do exemplo de apelido. O efeito usa try/catch/finally e o sinal ativo. Uma falha de leitura, parse ou formato mostra uma mensagem, sem gravar automaticamente os valores padrão. A função validarPerfil é definida no próximo slide. O operador spread devolve uma cópia do padrão.

AULA 19 / Guardar um objeto

JSON válido também precisa de formato

App.js · trecho em foco
function validarPerfil(valor) {
  return valor !== null && typeof valor === 'object'
    && typeof valor.apelido === 'string'
    && ['claro', 'escuro'].includes(valor.tema);
}

Formato esperado

apelido deve ser texto.
tema deve ser claro ou escuro.

Formato inesperado

Mostre a falha e permita restaurar o padrão.

JSON.parse verifica a sintaxe do JSON; não garante o formato de negócio. Exemplos inválidos: null, [], {apelido: 42, tema: "azul"}. O app valida antes de aplicar os dados e não sobrescreve automaticamente o armazenamento em caso de erro. A validação aceita campos extras sem usá-los.

AULA 19 / SecureStore

Secure storage com Expo SecureStore

Uma opção para guardar pequenos valores sensíveis no dispositivo.

Proteção nativa

No Android, usa armazenamento criptografado com apoio do Keystore. No iOS, usa o Keychain.

Uso nesta aula

Um token fictício representa a sessão. Não vamos guardar senha nem criar um servidor de autenticação.

SecureStore protege o dado armazenado. A validade de um token continua sendo responsabilidade do servidor.

Não confunda criptografia com autenticação de uma pessoa ou autorização de uma requisição. Um token expirado pode continuar armazenado; um app real deve lidar com essa situação. Não coloque chave privada de servidor no aplicativo. Fonte: Expo SecureStore.

AULA 19 / SecureStore

A mesma ideia, outros métodos

API · use em funções async com try/catch
import * as SecureStore from 'expo-secure-store';

const CHAVE_TOKEN = 'aula19.token';

await SecureStore.setItemAsync(CHAVE_TOKEN, 'token-ficticio-da-aula');

const tokenSalvo = await SecureStore.getItemAsync(CHAVE_TOKEN);

await SecureStore.deleteItemAsync(CHAVE_TOKEN);

Use chaves com letras, números, ponto, hífen ou sublinhado: aula19.token.

SecureStore também recebe strings. A leitura retorna string ou null e pode rejeitar. Evite copiar @ e / das chaves do AsyncStorage: esses caracteres não fazem parte do formato aceito pelo SecureStore. Os três comandos ilustram operações separadas. Fonte: API SecureStore.

AULA 19 / SecureStore

2. Restaurar ao abrir

App.js · trecho da leitura inicial
// Dentro do useEffect, no Android/iOS:
async function restaurar() {
  try {
    const salvo = await SecureStore.getItemAsync(CHAVE_TOKEN);
    if (ativo) setToken(salvo);
  } catch {
    if (ativo) setMensagem('Não foi possível restaurar a sessão.');
  } finally {
    if (ativo) setCarregando(false);
  }
}
restaurar();

Durante a leitura, mostre “Restaurando sessão…”. Depois, apresente o estado encontrado.

Este é um trecho do efeito do arquivo completo. ativo é declarado como true antes da função e passa a false no cleanup, como no primeiro exemplo. O arquivo verifica Platform.OS antes de chamar a API: na web, apresenta uma orientação. Encontrar o token não valida a sessão junto a um servidor.

A ordem da confirmação

Primeiro gravar. Depois atualizar o estado e a mensagem. O exemplo não mostra o conteúdo do token.

O guard de plataforma impede chamadas na web também dentro dos handlers. O guard de carregamento evita uma ação enquanto a restauração ainda está pendente. As ações ficam desabilitadas quando ocupado está true. Em um fluxo real, setItemAsync receberia um token emitido pelo backend.

4. Sair e apagar o token local

App.js · exclusão no SecureStore
async function sair() {
    if (ocupado || carregando || Platform.OS === 'web') return;
    setOcupado(true);
    try {
      await SecureStore.deleteItemAsync(CHAVE_TOKEN);
      setToken(null);
      setMensagem('Sessão fictícia removida.');

      setMensagem('Não foi possível sair. Tente novamente.');

      setOcupado(false);

Limpar a sessão local

A exclusão persistida acontece antes de setToken(null). Uma falha mantém o estado e permite tentar novamente.

Este é um logout local de demonstração. Em produção, pode haver revogação no servidor e limpeza de dados privados em cache. Não afirmamos que a simples exclusão local revoga todas as sessões em todos os aparelhos.

Erros que explicam muitos bugs

SintomaVerifique
Voltou o valor antigoAtualizou só o estado? A gravação foi aguardada?
O valor salvo sumiu ao abrirUm efeito gravou o estado vazio antes da leitura?
O objeto não foi recuperadoUsou stringify/parse e validou o formato?
SecureStore falhou no navegadorO exemplo está sendo executado em Android/iOS?
O apelido reapareceu após limparLimpou a chave persistida e o estado da tela?
Use as perguntas para depuração em sala. Também confira se a chave é idêntica na gravação e na leitura. clear do AsyncStorage não remove um token guardado no SecureStore. Nenhum desses storages sincroniza automaticamente dispositivos.

Antes de entregar, demonstre

TesteResultado esperado
Primeira aberturaValores padrão, sem falha por chave ausente.
Salvar e reabrirO último valor salvo é recuperado.
Editar sem salvar e reabrirO valor persistido continua igual.
Remover / sair e reabrirA chave removida não é restaurada.
Durante leitura e escritaA interface mostra o estado e bloqueia ações concorrentes.
Evite avaliar apenas com Fast Refresh. Se houver erro, confirme que o app não informa sucesso. É possível discutir falhas de armazenamento por indisponibilidade ou dados inválidos sem pedir que os alunos encham o dispositivo. No perfil JSON, mostre a necessidade de validação do formato.

AULA 19 / Revisar e consultar

Você consegue explicar?

Clique ou use Enter para revelar cada resposta.

Por que useState sozinho não resolve a persistência?

Ele mantém o estado da interface em memória. Após reiniciar, precisamos ler o valor persistido para restaurá-lo.

Um token pode ir no mesmo JSON do tema?

Nesta aula, o tema vai para AsyncStorage e o token para SecureStore, em chaves separadas.

Encontrar um token local prova que o login é válido?

Não. Em um app real, o servidor precisa validar o token, inclusive sua expiração ou revogação.

Abra uma resposta por vez para discussão. Retome a diferença entre proteger o valor em repouso e autorizar uma requisição. A separação dos dados permite manter preferências enquanto removemos a sessão.
