AULA 20 / APRESENTAÇÃO DO SQLITE

SQLite

Banco de dados completo

  • Banco relacional com SQL
  • Dados estruturados e complexos
  • Consultas avançadas
SQLite é um banco embutido: funciona dentro do aplicativo, sem um processo de servidor separado. Organiza registros em tabelas e permite filtros, ordenação, agregações e consultas que relacionam tabelas. No aplicativo móvel, os dados podem ser mantidos localmente e consultados offline. Fonte: SQLite · usos apropriados.

Limitações

O que considerar no aplicativo

  • Uma escrita por vez em cada banco
  • Não sincroniza dados entre dispositivos
  • Criptografia não vem ativada por padrão
Vários leitores podem coexistir, mas há apenas um escritor por vez em um banco. Isso atende muitos aplicativos locais; uma carga com muitas escritas simultâneas pode exigir outra arquitetura. Sincronizar aparelhos requer uma camada adicional. O SQLite padrão não é um cofre de segredos; no Expo, SQLCipher exige configuração e uma compilação compatível, enquanto pequenos segredos podem ser tratados com SecureStore. Fontes: SQLite · concorrência e usos e Expo SQLite · configuração de criptografia.

Importação e inicialização

import { useEffect } from 'react';
import { Text, View } from 'react-native';
import { initDB } from './db';

export default function App() {
  useEffect(() => {
    async function iniciar() {
      try {
        await initDB();
        console.log('Banco inicializado!');
      } catch (error) {
        console.error('Erro ao iniciar banco:', error);
      }
    }

    iniciar();
  }, []);

  return (
    <View>
      <Text>Meu aplicativo</Text>
    </View>
  );
}

Atividade

  • No App.js, importe initDB de ./db.
  • Reproduza a chamada no useEffect, com async/await e try/catch.
  • Execute o app e confira “Meu aplicativo” na tela.
  • Confirme “Banco inicializado!” no console.
App.js importa initDB de db.js, na mesma pasta. O efeito chama a função interna iniciar, que aguarda a preparação do banco. try/catch registra o sucesso ou o erro no console, enquanto a tela exibe Meu aplicativo. O callback do useEffect permanece síncrono; a função iniciar é async. Pause para os alunos reproduzirem o exemplo e mostrarem a mensagem de sucesso no console antes de seguir.

INSERT · Adicionar usuário

export async function insertUsuario(nome) {
  if (!db) throw new Error('Chame initDB() antes.');
  if (!nome.trim()) throw new Error('Informe o nome.');

  const result = await db.runAsync(
    'INSERT INTO usuarios (nome) VALUES (?);',
    [nome.trim()]
  );

  return result.lastInsertRowId;
}

Atividade

  • Em db.js, exporte insertUsuario(nome).
  • Use runAsync com ? para gravar o nome.
  • Retorne lastInsertRowId.
Acrescente esta função após initDB no mesmo db.js. A tabela usuarios já foi criada. O parâmetro ? recebe o nome como dado, sem concatená-lo ao SQL. Os valores são enviados em um array. A função rejeita a chamada antes da inicialização e o nome vazio. lastInsertRowId identifica o novo registro. Não inclua o INSERT dentro de initDB: a inicialização prepara a estrutura e a nova função cadastra o dado.

Cada execução da rotina pode criar uma nova linha; em desenvolvimento, Strict Mode pode repetir o efeito. Isso é uma demonstração de INSERT, não um cadastro disparado por um botão. Em uma tela de cadastro, a chamada deve acontecer por uma ação explícita. O auto-animate mantém o bloco de código e a atividade durante a passagem da função para seu uso.

UPDATE · Atualizar usuário

export const updateUser = async (id, nome) => {
  if (!db) throw new Error('Chame initDB() antes.');
  if (!nome.trim()) throw new Error('Informe o nome.');
  const result = await db.runAsync(
    'UPDATE usuarios SET nome = ? WHERE id = ?;',
    [nome.trim(), id]
  );
  return result.changes > 0;
};

Atividade

  • Em db.js, exporte updateUser(id, nome).
  • Atualize apenas o nome do ID recebido.
  • Envie os valores como parâmetros.
  • Retorne result.changes > 0.
Adaptamos o exemplo à tabela usuarios (id, nome), sem acrescentar email ou idade, que não existem no esquema apresentado. O primeiro parâmetro do SQL é nome e o segundo é ID. WHERE limita a atualização ao registro escolhido. changes maior que zero indica que uma linha foi afetada; um ID ausente devolve false. Atualizar para o mesmo nome não deve ser interpretado como prova de mudança no conteúdo: changes indica linhas afetadas pelo comando.

DELETE · Remover usuário

export const deleteUser = async (id) => {
  if (!db) throw new Error('Chame initDB() antes.');
  const result = await db.runAsync(
    'DELETE FROM usuarios WHERE id = ?;',
    [id]
  );
  return result.changes > 0;
};

Atividade

  • Em db.js, exporte deleteUser(id).
  • Mantenha WHERE id = ?.
  • Retorne result.changes > 0.
  • Teste um ID existente e outro inexistente.
A operação remove apenas o usuário do ID informado. DELETE sem WHERE removeria todas as linhas da tabela; DROP TABLE removeria a estrutura. O retorno é true quando há linha afetada e false quando não há. Não coloque esta função dentro de initDB, pois a inicialização não deve apagar os dados.

Atividade

O arquivo de conferência é AppDelete.js; App.js contém essa última etapa. Use um ID conhecido e confirme que getById devolve null após a exclusão. Um ID já excluído devolve false em deleteUser. Recarregar este exemplo executa a tentativa de exclusão novamente; em desenvolvimento o efeito também pode repetir. Esta é uma demonstração do comando, não uma recomendação de excluir dados automaticamente na abertura de um app real.
