Apresente o desafio de listar os títulos das notas, criar uma nota com título e conteúdo e cancelar sem salvar. Mantenha a contagem e uma mensagem de lista vazia. As ilustrações são referências visuais. A seção seguinte sugere a organização em db, repository e service com SQLite, para a turma implementar.

ARQUITETURA SUGERIDA

Um papel para cada camada

Telas→Service→Repository→DB · SQLite

Organização dos arquivos

App.js

db
Abre notas.db e cria a tabela notas.
repository
Executa o SQL para listar e inserir notas.
service
Valida título e conteúdo antes de salvar.
telas
Exibem os dados, recebem o texto e chamam o service.
Proposta de organização para a turma implementar, retomando a persistência SQLite da aula 20. App.js configura a navegação e aguarda a inicialização do banco antes de liberar as telas. database.js concentra a conexão e a criação da tabela. NotaRepository.js usa essa conexão; NotaService.js importa o repository; as telas importam o service. Os resultados e erros retornam no sentido inverso das chamadas. O estado dos campos fica no editor e o estado da lista fica na tela de listagem. Os exemplos antigos em memória não implementam esta arquitetura.

MODELO DO DADO

Uma nota, três campos

Objeto retornado pelo repository

{
  "id": 1,
  "titulo": "Ideias do projeto",
  "conteudo": "Criar meu app."
}

Tabela no banco notas.db

CREATE TABLE IF NOT EXISTS notas (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  titulo TEXT NOT NULL,
  conteudo TEXT NOT NULL
);
CampoRegra
idInteiro único, gerado pelo banco. O formulário não envia esse campo ao criar.
tituloTexto obrigatório. Pode se repetir: quem identifica a nota é o ID.
conteudoTexto obrigatório, com suporte a várias linhas.

O service aplica trim() nos textos e rejeita campos vazios antes de chamar o repository.

O JSON representa o formato do objeto JavaScript retornado pela consulta; no SQLite, cada nota é uma linha da tabela, não um arquivo JSON. O repository insere apenas titulo e conteudo e devolve o objeto completo com o ID gerado. Use parâmetros na consulta: INSERT INTO notas (titulo, conteudo) VALUES (?, ?). Nunca monte SQL concatenando o texto digitado. Na FlatList, converta o ID para string no keyExtractor: item => String(item.id). Não use o índice ou o título como identidade. O service deve validar o texto mesmo que os campos já tenham validação visual.

OPERAÇÕES E FLUXO

O que cada arquivo oferece

CamadaFunção sugeridaResultado ao concluir
dbinicializar()Banco e tabela prontos.
repositorylistar()Array de notas; [] se estiver vazio.
repositorycriar({ titulo, conteudo })Nota salva com o ID gerado.
servicelistar()Notas obtidas pelo repository.
servicecriar({ titulo, conteudo })Nota validada e salva pelo repository.
  1. Abrir a lista: aguarde service.listar() e atualize a tela. Recarregue ao voltar do editor.
  2. Salvar: aguarde service.criar(), desative o botão durante a gravação e volte após o sucesso.
  3. Cancelar: volte sem chamar o service. Se houver erro ao salvar, mantenha o rascunho e mostre a mensagem.
As operações de banco e as funções do service são assíncronas: os resultados descritos na tabela são os valores obtidos após await. A lista deve mostrar carregamento, erro ou estado vazio conforme o resultado. Recarregue os dados quando a tela receber foco após salvar uma nota. Em caso de falha na inicialização, informe o erro antes de permitir operações. Em uma gravação, use try/catch/finally para informar falhas e reativar o botão. O repository pode listar por id DESC para mostrar as notas mais novas primeiro. A tela nunca executa SQL. O escopo aqui é listar e criar; edição e exclusão não são necessárias para esta proposta.
